# TG Classic для Telegram Desktop

Это отдельный проект в `/Users/it_admen/Projects/telegram-classic` со своим Git-репозиторием. Он не находится внутри репозитория WECID.

Собран нативный Telegram Desktop с оформлением XP Classic по согласованному изображению. Интерактивный браузерный предпросмотр сохранён отдельно.

Перенос на другие платформы: [Android](android/README.md) и [Windows](windows/README.md). Оба клиента собраны. Подписанный Android APK проверен на Android 15 до входа в аккаунт, Windows x64 ZIP успешно запущен в отдельном пустом профиле Windows CI. Сохранены иконка TG Classic и классическое оформление.

Локальные пакеты находятся в `artifacts/android/TG-Classic-Android-arm64.apk` и `artifacts/windows/TG-Classic-Windows-x64.zip`. Windows: распаковать папку целиком и открыть `TG Classic.exe`. Android: установить APK ARM64 на Android 6.0+. Это тестовые сборки с ограниченными реквизитами upstream; перед публичным выпуском требуются собственные [Telegram API ID и Hash](https://core.telegram.org/api/obtaining_api_id).

[Успешная сборка Windows](https://github.com/cockroach55kg/tg-classic/actions/runs/40186825974) и [проверка запуска пакета](https://github.com/cockroach55kg/tg-classic/actions/runs/40212157556). Архивы Actions хранятся 30 дней; для скачивания артефактов нужен вход в GitHub. Исходники и сценарии сборки открыты, постоянные ключи подписи и профили в репозитории отсутствуют.

Приложение хранит собственные данные отдельно от установленного Telegram. Фон выбирается в настройках чатов. Его можно скрыть или снова показать через меню «View > Show chat wallpaper»; удаление картинки находится в настройках чатов.

При установке сохраняется и файловый объект самой папки приложения, чтобы ярлыки могли отследить переименование. Содержимое профилей при проверках не читается.

## Предпросмотр

Открыть `preview/index.html` можно через локальный сервер:

```sh
python3 -m http.server 8767 --bind 127.0.0.1 --directory preview
```

Затем открыть http://127.0.0.1:8767/ и нажать «Фон чата...». В предпросмотре работают выбор картинки, включение, отключение, удаление и сохранение после обновления страницы.

Это самостоятельный макет с демонстрационными сообщениями. Он не подключается к Telegram. Его успешные проверки не подтверждают работу нативного клиента.

## Исходники

Основа: официальный Telegram Desktop `v7.3.3`, точные ревизии и SHA-256 патчей записаны в `manifest.json`.

- `patches/tdesktop.patch` содержит изменения приложения.
- `patches/lib_ui.patch` содержит изменения его библиотеки отрисовки. Этот патч нужен отдельно, поскольку `Telegram/lib_ui` является подмодулем Git.
- `apply.py` получает закреплённую версию и проверяет оба патча до применения.
- `build.py` проверяет окружение, готовит зависимости по официальным процедурам и запускает Debug-сборку.

Подготовка новой копии исходников:

```sh
python3 apply.py
python3 apply.py --check
python3 build.py --check
```

Для существующей копии можно передать `--source /path/to/tdesktop`. Сценарий не сбрасывает чужие изменения и откажется применять несовместимый патч.

## Сборка Windows и macOS

На этом Mac используется отдельная конфигурация: macOS 14, arm64, Apple Command Line Tools, CMake/Ninja, Qt 6.11.2 и Debug с `-O1 -g0`. Параметры и закреплённые зависимости находятся в `local-mac/dependencies.json`, исходники и результаты зависимостей в `local-mac/src` и `local-mac/prefix`, журналы в `local-mac/logs`.

Все зависимости для этой локальной конфигурации уже подготовлены. Продолжение сборки с сохранённых результатов:

```sh
python3 tools/build-mac-local.py client
```

`tools/package-mac-local.py` собирает отдельный пакет в `artifacts/TG Classic.app` и проверяет локальную ad-hoc подпись. `tools/verify-mac-package.py` проверяет, что все несистемные загружаемые библиотеки находятся внутри пакета. Сценарий упаковки не заменяет существующий результат. Пакет предназначен для этого Mac, использует тестовые реквизиты upstream и не имеет нотариализации Apple.

Рабочая копия Qt расположена в `local-mac/qt`. `tools/prepare-local-qt.py` копирует установленные пакеты Qt и меняет пути к локальным библиотекам только в этой копии. Совместимость привязок wallet-engine с Apple Clang 15 обеспечивается отдельным `patches/wallet-clang15.patch`, применяемым после официального `wallet-engine.patch` из закреплённого репозитория desktop-app/patches.

Стандартная универсальная процедура upstream требует полного Xcode и указывает приблизительно 55 ГБ свободного места. Приведённый ниже `build.py --prepare` использует именно стандартную процедуру, а не конфигурацию `local-mac`.

Для Windows нужны отдельная Windows-среда, инструменты Visual Studio и Windows SDK из инструкции закреплённой версии Telegram. Windows x64 собран на Windows runner GitHub Actions; проверены контрольная сумма ZIP, запуск с пустым профилем и создание нативного окна в течение 15 секунд. Оформление внутри авторизованных Windows-чатов пока не проверено.

Зависимости располагаются рядом с `tdesktop`, как того требует upstream. Перед запуском `--prepare` необходимо выполнить установку инструментов из официальной инструкции для выбранной системы.

Для локальной разработки доступны ограниченные тестовые реквизиты upstream:

```sh
python3 build.py --prepare --test-api
```

Для обычного использования нужны собственные реквизиты приложения Telegram API. Они читаются из переменных `WECID_TELEGRAM_API_ID` и `WECID_TELEGRAM_API_HASH`:

```sh
python3 build.py --prepare
```

Тестовые реквизиты не предназначены для распространения клиентской сборки. В пакете нет пользовательских сессий или реквизитов приложения.

Ожидаемые результаты после успешной сборки: `tdesktop/out/Debug/TG Classic.app` на macOS или `tdesktop/out/Debug/TG Classic.exe` на Windows. Подпись и создание установщика остаются отдельными шагами после проверки приложения.
