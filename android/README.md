# TG Classic Android

Самостоятельный Android-клиент на закреплённых исходниках Telegram 13.0.3. Идентификатор `com.tgclassic.client.web` позволяет установить его рядом с официальным приложением. Минимальная версия Android 6.0, архитектура arm64-v8a.

Статус android-r1-compact: собран и подписан тестовый APK ARM64. На Android 15 проверены холодный запуск, работа окна в течение 15 секунд без падения, светлый и тёмный экраны приветствия и окно разрешения перед входом. Иконка сохранена побайтово. Изменения Android не затрагивают установленный клиент macOS.

Рекомендуемый локальный файл: `artifacts/android-compact/TG-Classic-Android-arm64.apk` (53 535 765 байт). SHA-256: `093e1762a7cfaf076c686dae8338d358d4505d9e939d50c4364c43a2e4e10f64`. Предыдущий APK размером 61 380 074 байта сохранён в `artifacts/android/`. Размер уменьшен на 12,78% через R8 и сжатие APK. Все 7672 файла ресурсов, assets и нативных библиотек совпадают побайтово; удаление ресурсов отключено. Подпись использует прежний постоянный ключ. Это личная тестовая сборка с ограниченными реквизитами upstream. Для публичного выпуска нужны собственные реквизиты API: [инструкция Telegram](https://core.telegram.org/api/obtaining_api_id).

Оформление использует серые панели, синие заголовки, прямоугольные сообщения, объёмные рамки кнопок и полей. Сохранена существующая иконка TG Classic. Тёмная палитра переключается штатными настройками Telegram. В меню чата добавлен переключатель отображения фона. Выбранная картинка сохраняется при скрытии; выбор своей картинки остаётся в настройках оформления Telegram.

`manifest.json` закрепляет upstream-коммит, контрольные суммы патча и всех добавленных файлов. `apply.py` проверяет их до применения и не сбрасывает несовместимые изменения.

```sh
python3 android/apply.py
python3 android/apply.py --check
TGCLASSIC_TEST_API=true python3 android/build.py --check
TGCLASSIC_TEST_API=true python3 android/build.py --compact
python3 android/sign.py --input artifacts/android-compact/TG-Classic-Android-arm64-builder.apk --output artifacts/android-compact/TG-Classic-Android-arm64.apk
```

Для обычной сборки вместо тестового флага задаются собственные `TGCLASSIC_API_ID` и `TGCLASSIC_API_HASH` или локальный файл `.private/telegram-api.json` с полями `api_id` и `api_hash`. Тестовый флаг явно включает общедоступные реквизиты разработки upstream и предназначен для личной проверки. Секреты не передаются через аргументы команд и не выводятся скриптом.

Флаг `--compact` включает минификацию кода с правилами сохранения upstream и оставляет все ресурсы. Без флага доступна исходная отладочная сборка. CI по умолчанию использует компактный вариант; переключатель `compact` позволяет выбрать исходный. Файл `mapping.txt` рядом с промежуточным APK сохраняется для разбора стеков ошибок R8.

Требуются Java 17, Gradle 8.13, Android SDK 36, Build Tools 36.0.0, NDK 27.2.12479018 и CMake 3.22.1. Локальные инструменты этого Mac находятся в игнорируемой папке `android/local/`. Компактная сборка создаёт промежуточный `artifacts/android-compact/TG-Classic-Android-arm64-builder.apk` с временной подписью. `sign.py` подписывает итоговый APK постоянным локальным ключом и проверяет подпись, пакет, минимальную версию Android, архив, наличие нативной библиотеки Telegram и выравнивание APK на 16 КБ. Обе нативные библиотеки также имеют ELF LOAD alignment 16 КБ.

Повторная проверка запуска выполняется командой `python3 android/verify.py --reset --apk artifacts/android-compact/TG-Classic-Android-arm64.apk --output evidence/android-compact` только в собственном эмуляторе `TGClassicQA`. Сценарий отказывается работать с физическими устройствами и другими профилями. Локальные результаты и снимки находятся в `evidence/android-compact/` и `evidence/android-r1/`; пользовательские данные не включены в репозиторий.

Ключ и пароль подписи находятся только в `.private/android/`. Эта папка исключена из Git. Её нужно сохранить для будущих обновлений Android-клиента. Ключ не загружается в GitHub Actions. Рабочий процесс CI выдаёт только промежуточный APK, после загрузки он подписывается на этом Mac тем же постоянным ключом.

Собственный Firebase-проект пока не настроен, upstream Firebase не используется. Доставка уведомлений в фоне требует отдельной проверки на устройстве. Прохождение компиляции не подтверждает вход, звонки, запись, получение сообщений или визуальное качество каждого экрана. Системные уведомления и маска иконки зависят от Android и оболочки устройства.
